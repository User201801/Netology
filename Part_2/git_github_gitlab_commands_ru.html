1. Git — команды по алфавиту

Исходные команды отсортированы по названию подкоманды.

01

git add -A

Подготавливает все новые, изменённые и удалённые файлы во всём рабочем дереве.

Важно. Перед массовым добавлением проверьте git status и git diff --cached.
Параметры команды ⌄
add
Обновляет индекс — область подготовки следующего коммита.
-A / --all
Учитывает новые файлы, изменения и удаления.
Примеры с описанием ⌄
git add -A

Подготовить все изменения.

git add -A src/

Подготовить изменения только внутри src/.

git diff --cached

Проверить содержимое индекса.

02

git add имя_файла

Помещает текущую версию выбранного файла в индекс.

Примечание. Если после git add файл изменился снова, выполните git add ещё раз.
Параметры и обозначения путей ⌄
add
Обновляет индекс содержимым выбранных путей.
имя_файла
Путь к одному файлу, например README.md или src/app.js.
каталог/
Путь к каталогу. Git обработает подходящие файлы внутри него и во вложенных каталогах.
.
Специальный путь: текущий каталог и всё его содержимое. Это не параметр с дефисом, а pathspec — обозначение выбранного пути.
--
Обозначает конец параметров. Всё после -- Git воспринимает как пути, даже если имя начинается с дефиса.
-p / --patch
Интерактивно выбрать отдельные фрагменты изменений вместо добавления файла целиком.
Примеры с описанием ⌄
git add README.md

Подготовить один файл.

git add src/

Подготовить изменения внутри каталога src и его вложенных каталогов.

git add .

Подготовить изменения в текущем каталоге и ниже. Если команда выполняется из корня репозитория, она охватывает весь рабочий проект.

git add -- "Мои документы/"

Подготовить каталог с пробелами или кириллицей.

git add -- -archive/

Подготовить каталог, имя которого начинается с дефиса.

git add -p README.md

Интерактивно выбрать отдельные фрагменты файла.

03

git branch

Показывает локальные ветки; текущая ветка отмечается звёздочкой.

Параметры команды ⌄
branch
Просмотр и управление ветками.
-a / --all
Показать локальные и удалённо-отслеживаемые ветки.
-vv
Показать последние коммиты и upstream-связи.
Примеры с описанием ⌄
git branch

Показать локальные ветки.

git branch -a

Показать все известные ветки.

git branch -vv

Показать upstream и состояние отслеживания.

04

git branch -d new-branch

Удаляет локальную ветку, если её изменения уже слиты.

Важно. -D может сделать неслитые коммиты недоступными по имени ветки.
Параметры команды ⌄
-d / --delete
Безопасное удаление слитой ветки.
-D
Принудительное удаление.
new-branch
Имя удаляемой ветки.
Примеры с описанием ⌄
git switch main
git branch -d new-branch

Переключиться и безопасно удалить ветку.

git branch -D abandoned

Принудительно удалить локальную ветку.

git push origin --delete new-branch

Удалить ветку на сервере.

05

git branch new-branch

Создаёт ветку на текущем коммите, но не переключается на неё.

Параметры команды ⌄
new-branch
Имя новой ветки.
[точка_старта]
Необязательная база ветки.
Примеры с описанием ⌄
git branch new-branch

Создать ветку и остаться в текущей.

git branch hotfix main

Создать hotfix от main.

git switch -c new-branch

Создать и сразу переключиться.

06

git checkout --ours Readme.md

Во время конфликта выбирает вариант файла со стороны ours; после этого нужен git add.

Важно. При rebase смысл ours/theirs может казаться обратным; проверяйте итоговый файл.
Параметры команды ⌄
--ours
Выбрать сторону ours.
Readme.md
Путь конфликтующего файла.
--theirs
Выбрать противоположную сторону.
Примеры с описанием ⌄
git checkout --ours README.md
git add README.md

Выбрать ours и отметить конфликт разрешённым.

git restore --ours README.md
git add README.md

Современная специализированная форма.

git checkout --theirs README.md
git add README.md

Выбрать theirs.

07

git checkout -b имя_ветки

Создаёт новую ветку от текущего коммита и сразу переключается на неё.

Параметры команды ⌄
-b
Создать ветку и переключиться.
имя_ветки
Имя новой ветки.
[точка_старта]
Необязательная база ветки.
Примеры с описанием ⌄
git checkout -b feature/login

Создать ветку от HEAD.

git checkout -b hotfix main

Создать ветку от main.

git switch -c feature/login

Современный эквивалент.

08

git checkout main

Переключает рабочую директорию и индекс на существующую ветку main.

Примечание. Git может отказаться переключаться, если будут перезаписаны незакоммиченные изменения.
Параметры команды ⌄
main
Имя локальной ветки.
Примеры с описанием ⌄
git checkout main

Классический вариант.

git switch main

Современный вариант.

git switch -

Вернуться на предыдущую ветку.

09

git checkout хэш

Открывает состояние указанного коммита и переводит HEAD в detached HEAD.

Важно. Коммиты в detached HEAD легко потерять из вида, если не создать ветку.
Параметры команды ⌄
хэш
Полный или однозначный сокращённый ID коммита.
--detach
Явно выбрать отсоединённый режим.
Примеры с описанием ⌄
git checkout a1b2c3d

Открыть старый коммит.

git switch --detach a1b2c3d

Современный явный вариант.

git switch -c investigation

Сохранить работу в новой ветке.

10

git clone ссылка

Клонирует удалённый репозиторий, создаёт локальный каталог и remote origin.

Примечание. Fork создаётся на сайте GitHub/GitLab; git clone только копирует репозиторий.
Параметры команды ⌄
clone
Создание локальной копии.
ссылка
SSH- или HTTPS-URL.
[каталог]
Необязательное имя локального каталога.
--depth N
Ограничить глубину истории.
Примеры с описанием ⌄
git clone git@github.com:User201801/Netology.git

Клонировать по SSH.

git clone https://gitlab.com/group/project.git

Клонировать по HTTPS.

git clone URL project-local

Задать имя локального каталога.

11

git commit -m "Комментарий"

Создаёт коммит из содержимого индекса и записывает сообщение.

Параметры команды ⌄
commit
Создать снимок подготовленных изменений.
-m / --message
Передать сообщение в командной строке.
"Комментарий"
Краткое описание цели изменения.
Примеры с описанием ⌄
git commit -m "Добавить страницу контактов"

Создать коммит.

git commit -m "Исправить форму" -m "Проверять пустой email."

Заголовок и отдельный абзац.

git commit

Открыть редактор сообщения.

12

git commit --amend -m "комментарий"

Заменяет последний коммит новым: меняет сообщение и/или добавляет подготовленные изменения.

Важно. Хэш изменится; не переписывайте общую опубликованную историю без согласования.
Параметры команды ⌄
--amend
Пересоздать последний коммит.
-m
Задать новое сообщение.
--no-edit
Сохранить прежнее сообщение.
Примеры с описанием ⌄
git commit --amend -m "Исправить заголовок README"

Изменить сообщение.

git add forgotten.txt
git commit --amend --no-edit

Добавить забытый файл.

git show --stat HEAD

Проверить результат.

13

git config --global --list

Показывает параметры глобальной конфигурации пользователя.

Параметры команды ⌄
--global
Читать глобальную конфигурацию.
--list
Вывести пары ключ=значение.
--show-origin
Показать файл-источник.
Примеры с описанием ⌄

git config --list --show-origin --show-scope

Все области конфигурации.

14

git config --global core.autocrlf true

Включает нормализацию окончаний строк; типичная глобальная настройка Windows.

Важно. В командном проекте дополнительно фиксируйте правила в .gitattributes.
Параметры команды ⌄
core.autocrlf
Правило преобразования LF/CRLF.
true
LF→CRLF при извлечении, CRLF→LF при добавлении.
input
Только CRLF→LF при добавлении.
Примеры с описанием ⌄
git config --global core.autocrlf true

Распространённый вариант Windows.

git config --global core.autocrlf input

Частый вариант Linux/macOS.

git config --global --get core.autocrlf

Проверить значение.

15

git config --global core.quotePath false

Показывает не-ASCII символы в путях читаемо.

Примечание. Вариант core.quotepath обычно тоже работает, но в документации принято core.quotePath.
Параметры команды ⌄
core.quotePath
Ключ отображения путей.
false / off
Отключить экранирование символов выше 0x80.
Примеры с описанием ⌄
git config --global core.quotePath false

Сделать кириллические пути читаемыми.

git status

Проверить вывод.

git config --global --get core.quotePath

Проверить значение.

Параметры команды ⌄
core.safecrlf
Проверка обратимости преобразования строк.
warn
Предупредить и продолжить.

Отклонить небезопасное преобразование.
Примеры с описанием ⌄

git config --global core.safecrlf true

Строгий режим.

git config --global --get core.safecrlf

Проверить значение.

31

32

git rm --cached имя-файла

Удаляет файл из индекса, но сохраняет его локально.

Важно. Секрет остаётся в старых коммитах; его нужно отозвать и при необходимости очищать историю.
Параметры команды ⌄
rm
Удаление пути из индекса.
--cached
Не удалять локальный файл.
-r
Рекурсивно для каталога.
имя-файла
Путь.
Примеры с описанием ⌄
echo .env >> .gitignore
git rm --cached .env
git add .gitignore
git commit -m "Перестать отслеживать .env"

Типовой процесс.

git rm -r --cached build/

Перестать отслеживать каталог.

git rm -r --cached .

  && sudo mkdir -p -m 755 /etc/apt/keyrings \
  && out=$(mktemp) && wget -nv -O$out https://cli.github.com/packages/githubcli-archive-keyring.gpg \
  && cat $out | sudo tee /etc/apt/keyrings/githubcli-archive-keyring.gpg > /dev/null \
  && sudo chmod go+r /etc/apt/keyrings/githubcli-archive-keyring.gpg \
  && sudo mkdir -p -m 755 /etc/apt/sources.list.d \
  && echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/githubcli-archive-keyring.gpg] https://cli.github.com/packages stable main" \
     | sudo tee /etc/apt/sources.list.d/github-cli.list > /dev/null \
  && sudo apt update \
  && sudo apt install gh -y
